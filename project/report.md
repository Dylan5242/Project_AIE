# Отчёт о проекте

## Постановка задачи

Цель проекта: прогнозировать почасовую нагрузку на сервис на следующие 24 часа.

Вход:

- последние 168 часов истории `requests`;
- timestamp последнего наблюдения.

Выход:

- прогноз `requests` на следующие 24 часа.

Задача относится к регрессии временных рядов.

## Данные

Использован датасет Calgary-HTTP из Internet Traffic Archive:

https://ita.ee.lbl.gov/html/contrib/Calgary-HTTP.html

Это реальные HTTP-запросы к серверу University of Calgary CS. Raw-лог был агрегирован по часам. Итоговый датасет:

- файл: `data/processed/calgary_http_hourly.csv`;
- период: `1994-10-24 13:00:00` -> `1995-10-11 14:00:00`;
- размер: 8 450 почасовых точек;
- целевая переменная: `requests`.

## EDA

В notebook построены:

- график временного ряда за весь период;
- график последних 14 дней;
- средняя нагрузка по часу дня;
- средняя нагрузка по дню недели;
- heatmap `day_of_week x hour`.

EDA показывает выраженную суточную и недельную сезонность, поэтому в моделях использованы лаги `lag_24` и `lag_168`.

## Признаки

Использованные признаки:

- `hour`;
- `day_of_week`;
- `is_weekend`;
- `lag_1`;
- `lag_24`;
- `lag_168`;
- `rolling_mean_24`.

Для нейросети LSTM дополнительно использовалось окно истории длиной 168 часов.

## Разбиение данных

Разбиение сделано по времени, без shuffle:

- train: первые 70% окон;
- validation: следующие 15%;
- test: последние 15%.

Такой split нужен, чтобы не заглядывать в будущее при оценке временного ряда.

## Модели

Проверены модели:

- seasonal naive `lag_24`;
- seasonal naive `lag_168`;
- linear regression;
- random forest;
- histogram gradient boosting;
- PyTorch LSTM;
- tuned random forest;
- tuned histogram gradient boosting.

Для random forest и boosting был сделан небольшой подбор гиперпараметров на validation.

## Метрики

Использованы:

- MAE: основная метрика, понятна в единицах `requests/hour`;
- RMSE: дополнительно штрафует большие ошибки;
- sMAPE: относительная ошибка в процентах.

## Результаты на test

| model | MAE | RMSE | sMAPE |
|---|---:|---:|---:|
| random_forest_tuned | 45.02 | 67.03 | 46.49 |
| random_forest | 45.84 | 68.23 | 47.16 |
| hist_gradient_boosting_tuned | 46.67 | 69.46 | 47.43 |
| hist_gradient_boosting | 48.73 | 72.41 | 49.43 |
| pytorch_lstm | 49.52 | 75.44 | 51.39 |
| linear_regression | 58.19 | 82.67 | 58.27 |
| seasonal_naive_lag_24 | 60.75 | 89.52 | 61.95 |
| seasonal_naive_lag_168 | 61.30 | 91.77 | 63.22 |

## Выбор финальной модели

Финальная модель: `random_forest_tuned`.

Причины выбора:

- лучшая MAE на validation и test;
- работает лучше сезонных baseline;
- работает лучше LSTM на текущих данных;
- быстро делает inference;
- легко сохраняется и загружается через `joblib`;
- не требует GPU.

Параметры финальной модели:

```text
n_estimators=300
max_depth=16
min_samples_leaf=5
max_features=0.8
random_state=42
```

## Сервис

Сервис реализован на FastAPI:

- `GET /health`: проверка статуса, модели и данных;
- `GET /demo-request`: пример тела запроса из последних 168 часов датасета;
- `POST /predict`: прогноз на следующие 24 часа.

В `/predict` используется реальная сохранённая модель:

```text
models/random_forest_tuned.joblib
```

## Ограничения

- Датасет исторический и относится к конкретному веб-серверу.
- В сервисе нет переобучения по новым данным.
- Признаки простые, без праздничных дней и внешних событий.
- sMAPE может быть нестабильной при малых значениях `requests`.
